# Voluntary peer reproduction checklist

This is a blank protocol for actual participants, not a completed evaluation.
Use only the synthetic demo/public UI; do not enter private repositories or secrets.
Documentation, UX, accessibility and test-design feedback are welcome.

1. Record the exact repository commit, OS, Node/npm versions and date.
2. Follow the engine reviewer quick-start from a clean checkout. Record setup time
   separately from demo runtime; note dependency/network requirements and errors.
3. Confirm healthy4/4 and the seeded shipping-boundary failure expected0/actual5.
   Identify which operations/model responses are mocked and which assertions ran.
4. Explore the public dashboard demo. Note confusing labels, keyboard navigation,
   small-screen layout and whether the illustrative-data notice is clear.
5. Record expectations, actual behavior, reproducible steps and sanitized evidence.
6. If willing, file a bug/docs issue or PR using the templates. Include your own
   observations rather than a prewritten testimonial or artificial success result.
7. Maintainer: review the actual contribution, record the outcome, fix/retest as
   appropriate and credit the accepted work. Do not count an invitation as adoption,
   an AI role as a community member or an unrecorded estimate as measured savings.

Optional fields: participant's chosen public handle, discipline, experience level,
setup minutes, run minutes, confusion/bug count, issue/PR URL and outcome. Leave
unmeasured fields blank. Participant chooses what to publish; no student identity,
private email, credentials or product data is required.
